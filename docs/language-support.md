# Thai / English UI

Both HDC web applications use the same TH/EN header switch and required-field styling.
The switch is placed directly before the clock. Language is saved in localStorage as
`hdc-language` for the current origin. Switching language does not reset form state.

UI labels and instructions are translated through `src/lib/i18n.tsx` and
`src/lib/translations.json`. Add new display strings through `t()` and subscribe to
language updates using `useLanguage()` in their component. Dynamic strings use
numbered placeholders, e.g. `t("ภาพที่ {0}", index + 1)`.

Business values (operator/store/province names, registration numbers, IDs) remain
as entered. Truck type option values remain the Thai API values; only labels are
translated. Browser-native validation text follows the browser language. Exported
PDF content is generated by the backend and is not changed by this UI switch.

Required input/select/textarea controls are yellow in both apps. Optional plate
province remains optional. Checkbox, radio and file controls are excluded.

Validation: both production frontend builds passed. Browser checks at 360px width
passed for language switching, reload persistence, preserved form values, yellow
required fields, header button position and no horizontal page overflow. Entry and
working pages were exercised with mocked API responses; this does not certify
backend behavior or physical TC22 scanner/camera operation.
